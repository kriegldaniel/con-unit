05Narrowing the suspectsReplay

  1. 2:11Attribution is done by the evaluation tool tools/attribute_exec, not by con-unit test in version 0.3.0.
  2. 2:16The baseline runs and the treatment exits. Then each candidate path is made writable, one at a time.
  3. 2:22Making /var/cache writable restores liveness at W. The union of all candidates does too.
  4. 2:30The recorded status is RESOLVED_SINGLE. It is a lead for a recipe, not a proof.
  5. 2:36The same steps for the capability restriction. Dropping all capabilities makes the run exit.
  6. 2:40No single capability restores the run, but all candidates together do.
  7. 2:46Then capabilities are removed from the set one at a time, and the run is checked after each removal.
  8. 2:53The minimal set that restores liveness at W: CAP_CHOWN, CAP_NET_BIND_SERVICE.
  9. 2:57It is a lead for a recipe, not a proof.

07What this does not tell youSchematic

  1. 3:26Running at W is a liveness proxy, not proof that a service works.
  2. 3:30Attribution is done by the evaluation tool tools/attribute_exec, not by con-unit test.
  3. 3:33Tiers 1 and 2 overlap with linters like Dockle and the Anchore CIS pack.
  4. 3:37Tier 4 is an interface only and is not part of the evaluation.
  5. 3:40The profile is informed by CIS topics. It is not a CIS compliance assessment.
  6. 3:44Tier 3 starts the image with its own entrypoint. Use a disposable host.
  7. 3:47A baseline that fails or exits early gives UNVERIFIED, not a guess.
  8. 3:51Evaluated so far on rootful Podman 4.9.3, linux/amd64.
  9. 3:53Research prototype. Evaluation results are not repeated here.
