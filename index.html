Three suspects

  • The imageIt may need something that the restriction takes away.
  • The restrictionIt may be a setting that no image should be asked to meet.
  • The test setupThe flags, the environment or the engine may be the cause.

A dead container alone does not say which.

03

Chapter 3: The baseline clears or blames

Provenance:

Every restriction is judged against a baseline: the same image, started with only defensive flags. If the baseline did not stay up, there is nothing to compare with, and the tool says so instead of guessing.

The chart below applies one restriction, dropping all capabilities, to three recorded images. The observation window W is3.0 s.

No times inventedThe records carry states and exit codes, not exit times. A run that exited is drawn as a hatched bar over the whole window.

The rule

  1. The baseline fails to start or exits with a non-zero code: no verdict. UNVERIFIED, BASELINE_FAILED.
  2. The baseline exits with code 0 before W: no verdict. UNVERIFIED, NOT_OBSERVABLE.
  3. The baseline is still running at W: the restriction is judged. PASS if the restricted run is still running at W,FAIL otherwise.

The rule as the tool applies it.

What FAIL meansA FAIL means that the container was not running at the end of the window under the restriction although the baseline was. It is not a defect claim and not a root cause.

Chapter 6: Use it

Provenance:

It runs where tests run. The command writes a JUnit file and sets an exit code that a build can act on.

Exit codeExit code 1 when any check is FAIL or UNVERIFIED.

A run of the real binary

Exit code of this run: 1. <ref> stands for the digest pinned nginx reference of chapter 1.

Exit codes of the tool

  1. 0ExitOKcon-unit test: no result is FAIL or UNVERIFIED. con-unit eval: every attempted image produced a COMPLETED record.
  2. 1ExitFindings returned by the command abovecon-unit test: at least one result is FAIL or UNVERIFIED, or the engine, the pack, the run or a report file failed. con-unit eval: when --fail-on-findings is set and findings are present.
  3. 2ExitUsageInvalid flags or configuration.
  4. 3ExitIncompletecon-unit eval: at least one image ended in a non-COMPLETED status, or an output file could not be written.

Chapter 7: What this does not tell you

Provenance:Schematic

One limit at a time. Each statement has a source that you can open.

Silence is part of the messageThese are statements, not results. The tool is a research prototype.

  1. L02

    Tier 3 is a short liveness proxy. A container that is running at W may still fail later, or may not serve requests.

  2. L01

    A FAIL means that the container was not running at the end of the window under the restriction although the baseline was. It is not a defect claim and not a root cause.

  3. L09

    For an image whose baseline is still running, the baseline observation alone takes the window W. That is a property of the method and not a performance result.

  4. L03

    In version 0.3.0, failure attribution is done by the evaluation tool tools/attribute_exec. It is not a command of con-unit test.

  5. L12

    Removing any one element of the reported minimal set made the container fail again under the recorded flags. Several sets of the same size can exist, and the smallest possible set is not guaranteed.

  6. L04

    Tiers 1 and 2 overlap with image linters such as Dockle and the Anchore CIS policy pack.

  7. L05

    Tier 4 is an interface only and is not part of the evaluation.

  8. L06

    The hardening profile is informed by topics of the CIS Docker Benchmark. It is not a CIS compliance assessment.

  9. L07

    Tier 3 starts the image with its own entrypoint. Run it on a disposable host.

  10. L08

    If the baseline fails to start or exits non-zero, the Tier 3 results are UNVERIFIED with BASELINE_FAILED. If it exits 0 before W, they are UNVERIFIED with NOT_OBSERVABLE. A restriction is judged only when the baseline was still running at W.

  11. L10

    The tool was run on rootful Podman 4.9.3, linux/amd64. Other engines and platforms were not evaluated.

  12. L11

    Research prototype. Evaluation results are not repeated on this page.

08

Chapter 8: Try it

Provenance:

The commands below were run from a fresh clone on 2026-11-20. Each step lists the exit code and the time that it took. One step failed because of the setup, and its fix is part of the list. The two runs of con-unit test exit with 1 because the image has findings, as the exit code is meant to say.

What you need

  • Nix with flakes. The dev shell of the repository provides Go, just and the other tools.
  • A container engine, Podman or Docker, and it must be running. The recorded run used Podman.
  • Tier 3 starts the image with its own entrypoint. Run it on a disposable host.

Where this was runPodman 5.8.1, rootless, linux/arm64/v8, a clean clone of tageval-v1. The evaluation itself used rootful Podman 4.9.3 on linux/amd64, so this is a different setup.

What happened in the clean room

  1. 1just test 54 sFails in a fresh clone. The recipe sets GOPROXY=off and the module cache is empty, so module lookup is disabled.
  2. 0go mod download 3 sFills the module cache. Needed once.
  3. 0just test 22 sThe offline unit tests pass after the download.
  4. 0just build 1 sBuilds bin/con-unit.
  5. 1./bin/con-unit test alpine:latest 3 sExit code 1 because checks failed or are unverified.
  6. 1./bin/con-unit test alpine:latest --pack hygiene 1 sThe hygiene pack on the same image.
  7. 0./bin/con-unit rules 0 sPrints the rule reference.

What to expect from alpine:latest

./bin/con-unit test alpine:latest exits with code 1. In the recorded run, 2 checks failed (SPEC-01, CIS-4.6) and 5 were UNVERIFIED.

The runtime checks (EXEC-02, EXEC-07, EXEC-01, EXEC-04) are UNVERIFIED because the baseline run of alpine exited with code 0 before the observation window ended. Nothing was left running to observe, so the tool gives no verdict instead of a guess. That is the rule of chapter 3.

SUP-02 is the Tier 4 signature check. It is UNVERIFIED because no signature policy was given.

Your output may differalpine:latest moves over time, so details of the image can change. The time on the DURATION line is that of one run and is not a result.
